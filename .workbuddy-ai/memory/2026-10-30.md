### Decisions worth remembering

- **`lib/dashboard/format.ts` must stay Prisma-free.** `analytics.ts` imports
  `prisma`; importing any formatter from it inside a client component drags `pg`
  into the browser bundle and fails the build with `Can't resolve 'util/types'`.
- Filtering/sorting/paging are **URL-driven server-side**, not a client store, so
  views are shareable and survive refresh. Selection and the open drawer stay
  client-side.
- Price and revenue sorts cannot be a single `orderBy`: price lives in three
  columns by listing type, revenue lives on reservations. Both rank ids first
  (`listingComparablePrice`, annualised for monthly listings) and hydrate only
  the visible page.
- Bulk actions are exposed as `(ids: string[]) => Promise<BulkResult>` server
  actions — a wrapper closure created in a server component cannot be passed to a
  client component.
- Notifications are **derived** from state (pending reservations, drafts, fresh
  reviews), never stored, so they clear themselves when handled.
- `DetailStats` is always 2 columns: the drawer is ~400px wide, so a
  `sm:grid-cols-4` grid crushes money values (breakpoints are viewport-based).
